编写博客文档时，必须做到言简意赅、条理清晰。先梳理逻辑结构，再组织语言表达。不写废话，不重复陈述同一观点。每个段落只讲一件事，层层递进。

关键的地方可以加****加粗表示，但是物极必反，不能频繁地加，而是要精准地加。

`- `这种样式，多个连续多行中的`- `中的第一个`- `前面必须添加一个空行，否则这段连续的`- `不会自动换行。而是跟前面的文字紧贴着。

`> `这种要实现换行的话，两行之间必须插多一个`> `

！！！每当有一部分新内容要添加到文档里时，要整理清楚文章逻辑，思考应该在哪一个位置添加哪些内容，动态插入到文档中，而不是无脑地添加到文章的末尾。

！！！如果我想我Accept了你某个修改内容，但是你下一次写入其他内容的时候，发现用户手动对上一次Accept的内容做了调整，这时不要自作主张帮用户改回原来accept的内容，而是要提醒用户，让用户自己决定。

！！！spec/标准文档的引用（ARM ARM 规则 ID、SMMU spec 章节等）不要把英文原文整段堆在正文里。正文中只写：粗体规则 ID + 一句话中文人话要点（括号注明"原文见附录X"）；英文原文 + 中文翻译统一收录到文末"附录"（附录A = ARM ARM 规则索引，附录B = SMMU spec 索引），每条格式：`**规则ID** — 主题（spec章节）` + blockquote（英文原文 + 中文翻译）。附录中收录完整原文，不做截断。

！！！正文行文不要大段大段地堆叠文字。多个想法挤在一段里时：
- 要么拆成 `- ` 分点列表（每点只讲一件事，如果依然有内容冗余，可以加个二级的`-`，以此类推，分级沉淀一大段描述）
- 要么压缩成一句话；超过两句话的解释就应该考虑分点。spec 引用、代码块、表格、图不属于"大段堆叠"。

文章中有多处重复的内容，整理总结成一处，然后找到最合适的位置去写

如果是文章重构的话，遵循以下步骤：

- 遍历全文，总结最好的文档结构，内容分阶段说明
- 一开始先定义好概念，！！不要自行发明名词！！
- 写或者改文件前先通读，找到各处冗余重复的内容，整理总结合并成一处，然后找到最合适的位置去写
- 注意，要保证内容完整，逻辑合理，方便阅读
- 文章应该**意简言骇**
- **文档修改不要强调改了什么**：像“你之前是 X，现在改成 Y”这种更不应该出现在正文，改了啥就是啥，静默修改就行，不要在正文中汇报.
- 标题就是精炼的标题，不是提问，不要把用户提问的内容直白地写出来，而是整理成一个知识点展示出来。
- 文章表述方式要让**人的可读性高一些**
- 图片是易读的，所以重构后图片要尽可能保留
- 如果重构到后面的章节，review后发现有一些内容应该合并到前面，但是前面没有完成合并的，需要更新插入到前面的内容中。
- 图片放置顺序如果修改的话，有编号的图片，编号也得修改，正文中有提到引用了这个图片的话，正文提及的编号也要修改。

！！！交互式 HTML 动画（如 PlantUML 动图、JS 交互演示等）不要放在 `_posts/` 的 post 资产文件夹里——hexo 内置 `html → html` 直通 renderer，会把 `.html` 文件当作独立文章处理（标题为空 → 显示为 "[Untitled Post]"）。正确做法：在 `source/` 根目录下创建独立文件夹（如 `source/tlb-multihit/index.html`），并在 `_config.yml` 的 `skip_render` 中添加该目录（如 `- tlb-multihit/**`），让 hexo 原样复制不渲染——否则 hexo 会用主题模板包裹 HTML（注入 header/footer/JS），iframe 里会看到 Author/License 等主题元素。iframe 用绝对路径引用（如 `src="/tlb-multihit/index.html"`）。参考 `source/buddy-animation/` + `skip_render: - buddy-animation/**` 的结构。
